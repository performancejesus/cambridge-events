# Cambridge Events — бриф для Claude Code

## Что строим
Сборщик событий Кембриджа и окрестностей (до ~1 часа езды), который раз в неделю готовит черновик рассылки «что происходит на этой неделе и в выходные». Это MVP: всё работает локально, без облака, пока я не скажу иначе.

## Входные данные
`cambridge_event_sources_v0.3.xlsx` — реестр источников (лежит рядом с этим файлом):
- лист «Источники»: ID, категория, URL, способ сбора (RSS / iCal / API / HTML / ручной), приоритет 1–3, флаг «URL проверен»;
- лист «Схема события»: поля, которые нужно заполнять для каждого события (обязательны адрес, postcode, дата и время начала);
- лист «Категории и теги»: допустимые значения категорий и тегов.

## Этапы
Идём по одному. После каждого этапа — короткий отчёт мне и пауза до моего «дальше».

**Этап 1. Проверка источников с приоритетом 1.**
Для каждого: открыть URL и убедиться, что он живой; найти лучший способ сбора — RSS (`/feed`), iCal, JSON-LD `schema.org/Event` на странице, API, иначе HTML. Для строк без URL найти официальный сайт. Результат: обновлённый реестр в новом файле `cambridge_event_sources_v0.4.xlsx` (исходный не трогать) и таблица «что нашёл / что не получилось».

**Этап 2. Коллекторы для 15–20 лучших источников.**
Начать с тех, где есть готовые фиды: talks.cam.ac.uk (iCal/RSS/XML), календарь матчей Cambridge United, Cambridge 105, RSS блога Cambridge Foodies, Skiddle. Один модуль на источник, общий интерфейс.

**Этап 3. Нормализация и хранилище.**
SQLite (`events.db`) по схеме из реестра. Дедупликация: одно событие из нескольких источников — одна запись со списком источников. Геокодирование по postcode через postcodes.io и расчёт зоны: центр / до 30 мин / до часа.

**Этап 4. Черновик выпуска.**
Скрипт берёт события на ближайшие 7–10 дней и через Claude API отбирает лучшие и пишет короткие описания своими словами. Рубрики: главное на выходные, бесплатно, с детьми, спорт, за городом, успейте купить билеты, отменено/перенесено, новое в городе (открытия заведений — отдельный поток, не афиша). На выходе Markdown-файл.

**Этап 5. Контур отмен.**
Отдельный скрипт перепроверяет страницы уже отобранных событий на cancelled / postponed / sold out и обновляет статус.

**Этап 6 — только после моего подтверждения.** Запуск по расписанию.

## Правила
- Уважать robots.txt, делать паузы между запросами, честный User-Agent.
- Не парсить Facebook, Instagram, Nextdoor.
- Не копировать описания событий дословно: хранить ссылку на первоисточник и короткий пересказ.
- Ключи (Anthropic API и другие) — только в `.env`, не в коде и не в git.
- Перед подключением платных сервисов или любыми тратами — спросить меня.
- Python, простые зависимости: httpx, selectolax или BeautifulSoup, feedparser, icalendar. Playwright — только если без него никак.

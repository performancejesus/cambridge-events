# Cambridge Events — бриф для Claude Code (v3, обновлён 29.09.2026)

## Что строим
Сборщик событий Кембриджа и окрестностей, который раз в неделю готовит черновик рассылки «что происходит на этой неделе и в выходные». Помимо афиши сборщик отслеживает жизненный цикл событий (анонсы, старт продаж, отмены) и открытия новых заведений и магазинов. Это MVP: всё работает в облачной среде cambridge-events, без платных сервисов, пока я не скажу иначе.

## География
Зона покрытия = **всё, что в пределах часа езды от Кембриджа** + **весь Кембриджшир целиком**, включая Питерборо и Fenland, даже если туда дольше часа.
- Внутри зоны: Ньюмаркет, Saffron Walden, Royston, Haverhill, Бери-Сент-Эдмундс (соседние графства, но до часа) — да; Wisbech, March, Питерборо (Кембриджшир, но около часа и дальше) — да.
- Вне зоны: всё, что дальше часа И не в Кембриджшире (например, Бишопс-Стортфорд, если дальше часа, Лондон).
- Проверка принадлежности графству — по postcodes.io: `admin_county == "Cambridgeshire"` или `admin_district == "Peterborough"`.
- Метка зоны у события: `центр` / `до 30 мин` / `до часа` / `Кембриджшир, дальше часа`. Последняя метка нужна, чтобы в выпуске такие события шли отдельной рубрикой «По графству» и не вытесняли городские.

## Входные данные
`data/cambridge_event_sources_v0.5.xlsx` — реестр источников (листы «Источники», «Проверка P1», «Проверка P2», «Контрольные события», «Сводка», «Схема события», «Категории и теги»). Каждый этап, меняющий реестр, создаёт следующую версию рядом, прежние не трогает.

**Этап 3. Нормализация, хранилище и извлечение из статей.** ✅ Готово (`docs/stage3_report.md`): 440 будущих событий, 48 записей «Новое в городе», все контрольные примеры найдены, кроме ожидаемых (Town and Gown, Oktoberfest 2027). Расход на извлечение $0.64. Мелкие доработки — в разделе «Решения после этапа 3, часть 2», выполнить в начале этапа 4.
1. **База** `events.db` (SQLite) с жизненным циклом событий и таблицей `venue_news` (см. разделы ниже). Сырые данные каждого прогона складываются в базу, прошлые события не удаляются — хранится история.
2. **Дедупликация.** Одно событие из нескольких источников — одна запись со списком источников. Особое внимание: Corn Exchange (S011) и Cambridge Live Tickets (S091) — один оператор; концерты дублируются на Ents24 (S006) и Skiddle (S007). Ключ сравнения: нормализованное название + дата + площадка, с нечётким сравнением названий.
3. **Справочник площадок** `venues`: название и синонимы → адрес, postcode, координаты, зона. Заполнить из событий, где адрес есть; колледжи, музеи и аудитории университета (talks.cam даёт postcode только у 6% событий) — добавить вручную или через postcodes.io. Событие без postcode получает адрес из справочника по названию площадки.
4. **Геокодирование** по postcode через postcodes.io, зона — по правилам раздела «География». События вне зоны не удалять, а помечать `out_of_zone` и не показывать в выпуске.
5. **Извлечение из статей через Claude API.** RSS-источники (Cambridge Independent, Cambridge News, What's On In Cambridge, Cambridge Foodies, Fitzwilliam, новостные фиды Cambridge 105) дают статьи, а не события. Для каждой новой статьи модель определяет, есть ли в ней: (а) событие с датой и местом, (б) открытие или закрытие заведения/магазина, (в) отмена или перенос известного события, (г) старт продажи билетов. Результат пишется в соответствующие таблицы с пометкой `source_type = article` и ссылкой на статью. Статьи без полезного содержания помечаются и больше не обрабатываются. Использовать дешёвую модель (Haiku), промпт и JSON-схему хранить в репозитории.
6. **Цены.** Где цена не пришла структурно, попытаться извлечь её со страницы события или из текста; «Free»/«free entry» → 0. Нужно для рубрики «бесплатно».
7. **Инкрементальный сбор.** Для источников, где открываются страницы событий (S011, S072, S091 и подобные), запрашивать страницы только для новых ссылок; уже известные — не чаще раза в неделю или при проверке статуса.
8. **Разовая выгрузка архива Cambridge Foodies** через `/feed/?paged=N` (редкие запросы, паузы, стоп после 429) → через извлечение из статей в `venue_news` за последние 12 месяцев.

**Этап 4. Черновик выпуска.**
Первый выпуск: период с понедельника 28 сентября по воскресенье 11 октября 2026 (две недели, чтобы было из чего выбирать), «главное на выходные» — 3–4 октября. Дальше — выпуск раз в неделю по четвергам: события с пятницы по воскресенье следующей недели.
Через Claude API — отбор и короткие описания своими словами (для отбора и текста можно взять модель сильнее Haiku, например Sonnet; показать расход). Требования к тексту:
- объём — чтение на 5 минут: в каждой рубрике 3–6 пунктов, всего 25–40 пунктов;
- у каждого пункта: название, день и время, место (площадка + район или городок), цена или «бесплатно», 1–2 предложения своими словами, ссылка;
- тон — дружелюбный местный гид, без рекламных штампов;
- не повторять одно событие в нескольких рубриках;
- не включать события без площадки/адреса и лекции с «Title to be confirmed»;
- многодневные и регулярные события (серии спектаклей, выставки) — одним пунктом с диапазоном дат;
- в конце — служебный блок **«Для редактора»**: сомнительные пункты, дубли, которые не склеились, события с непроверенным статусом, что не попало и почему.
Язык: основной выпуск на английском (`issue_2026-10-01_en.md`) и тот же выпуск на русском (`issue_2026-10-01_ru.md`) — выберу, какой формат развивать.
**Первый выпуск и «новые анонсы»:** у всех событий `first_seen_at` — дни первых прогонов, поэтому в первом выпуске рубрика «Новые анонсы» строится не по `first_seen_at`, а по заметным событиям с датой дальше двух недель, которые объявлены недавно по данным источников (дата публикации статьи или анонса). Со второго выпуска — по `first_seen_at` за последние 7 дней. Не включать туда матчи из загруженного целиком календаря сезона.
Рубрики:
- главное на выходные;
- бесплатно; с детьми; спорт; за городом (до часа);
- по графству (Кембриджшир дальше часа: Питерборо, Fenland — только заметные события);
- новые анонсы (впервые появились за неделю, в т.ч. даты ежегодных событий);
- успейте купить билеты (продажа открылась или скоро откроется, мало билетов);
- отменено и перенесено;
- новое в городе (открытия ресторанов, кафе, баров, магазинов).

## Редакционные правки по черновику v5 (применять с v6)
- **Факт в «Теме недели» неверный.** «Сиду Барретту в этом месяце исполнилось бы 80 лет» — ошибка: он родился 6 января 1946 года. Любые даты рождения, юбилеи и «первый/последний/единственный» из знаний модели — в список «Факты из знаний модели (проверить)». Утверждение «сборы матча с Blackpool идут на благотворительность, по словам сестры» — сверить со статьёй-источником.
- **Правило «нет содержательного факта — не брать» сработало слишком жёстко.** Выпали Mill Road Winter Fair (6.8, контрольный пример брифа!), Sun Chariot Day и Dubai Future Champions Festival (крупнейшие скачки осени в Ньюмаркете), матчи Peterborough United. Новый порядок, если в данных нет фактов:
  1. одна загрузка страницы события у первоисточника;
  2. описание из `recurring_events` для ежегодных событий;
  3. для матчей — турнир, соперник, положение в таблице; для скачек — главный забег дня;
  4. для широко известных ежегодных событий модель может описать их по своим знаниям — с пометкой в «Факты из знаний модели».
  Пункт с оценкой ≥ 6 из-за нехватки фактов не выбрасывать: он идёт в выпуск с нейтральной фразой, а в «Для редактора» — пометка.
- **Мероприятия за городом в «Главное на выходные» — только при оценке ≥ 8.** В v5 «Главное» 10–11 октября — 2 из 3 пунктов вне Кембриджа (The Apex, Saffron Hall), а рубрика «За городом» осталась с 2 пунктами. Так же, как правило для графства: «до часа» с оценкой ниже 8 — в «За городом». В «Главном» — минимум 2 из 3–4 пунктов в Кембридже или до 30 минут.
- **«На неделе» — разнообразие.** В v5 все 4 пункта — Corn Exchange, ни одного театра: Footlights (6.2) и London City Ballet в Arts Theatre вытеснены. Правила:
  - не больше 2 пунктов с одной площадки в рубрике;
  - хотя бы 1 театр или танец, если есть кандидат с оценкой ≥ 4;
  - сортировать по дате (Joe Jackson 1 октября стоял третьим).
- **Минимум по рубрикам.** Если кандидатов с оценкой выше порога достаточно, в «Бесплатно», «Новые анонсы» и «За городом» — не меньше 3–4 пунктов. «Лучше меньше» — только когда кандидатов действительно нет.
  - В «Бесплатно» v5 было 2 пункта из 65 кандидатов; мимо прошли бесплатный органный концерт в King's College Chapel, Music Marathon в Great St Mary's, Meet the Cows в Wandlebury.
  - Библиотечные регулярные занятия — одной строкой «Регулярно в библиотеках: …».
- **«Бесплатно» — только действительно бесплатное.** Цена £0–£165 (Ultimate Rave Bingo) — это не «бесплатно»: так помечать, только если максимальная цена тоже £0. «Бесплатно при входном билете в сад» — не «бесплатно».
- **«Успейте купить билеты» — про срочность, а не про далёкие анонсы.** Simply Red, Olly Murs и Big Retreat на август 2027 года — это «Новые анонсы» («в продаже с …»). «Успейте» — только если есть сигнал:
  - «мало билетов», «selling fast» или «last few» на странице;
  - заканчивается ранняя цена или продажа;
  - событие в ближайшие 2–6 недель с высокой оценкой и ограниченным залом.
  Если сигналов нет — рубрику скрыть.
- **«Новые анонсы» — Mill Road Winter Fair обязательно** (5 декабря). Анонсы ежегодных событий из `recurring_events` с подтверждённой датой — главный кандидат рубрики.
- **«За городом» — досуг, а не гражданские мероприятия.** Публичная выставка проекта Cambridge South (консультация по застройке) — не туда. Такие мероприятия в выпуск пока не брать; идея рубрики «Город и жители» — в бэклог.
- **«Новое в городе»:**
  - сначала Кембридж; из других городков зоны — не больше 1–2 пунктов, с названием городка в заголовке строки (Ephesus — «Saffron Walden, 25 мин»);
  - если дата открытия = дата статьи, не писать «Открылось 17 августа»: писать месяц («открылось в августе») или «недавно открылось»;
  - добавить подтверждённые открытия 6b (Arbury Social, Bridge Bagels, Marvin's на Mill Road, магазины в Grand Arcade и The Grafton), если они попадают в окно «последние 2 месяца».
- **Цена для выбранных пунктов.** «Цена не указана» у Saffron Hall, The Apex, Cambridge United, Town & Gown — для каждого пункта выпуска без цены сделать одну загрузку страницы у первоисточника (сайт площадки, клуба, продавца билетов). Не нашлась — писать «цены на сайте», а не «цена не указана». Для забегов — «смотреть бесплатно» для зрителей.
- **Описания пунктов с оценкой ≥ 8 — 2–3 предложения.** Проверка ответа уже ловит нарушение (7 пунктов в v5); теперь такие пункты автоматически перегенерировать одним дополнительным запросом, а не только отмечать.
- **Английские слова в русском тексте:** «запись открывается: mid-November» → «в середине ноября». Проверка алфавита должна ловить латиницу вне названий.
- **Счётчик в редакторской версии при склейке.** В «Теме недели» написано «6 (в выпуске 6)», а пунктов 5: встреча с режиссёром и показ фильма объединены в один пункт. Писать «6 событий → 5 пунктов (2 объединены)», объединённые события помечать в списке.
- **ADC Theatre должен быть виден.** События есть (Footlights, CAST King Lear, We Will Rock You), но у King Lear и We Will Rock You оценка 2.3 — нет цены, маленький зал. Цены ADC брать со страницы продажи билетов. Студенческий театр ADC — кандидат на обязательный театральный пункт «На неделе» (правило о разнообразии выше).
- **Семейные события — кандидаты в «С детьми» из любой зоны.** The Gruffalo на Nene Valley Railway стоял в общей рубрике «вытеснен более сильными». Семейные события за городом — в «С детьми» с пометкой зоны (пороги зон те же). События в дни каникул (Gruffalo — 25 октября) — в подраздел «Каникулы → Куда сходить с детьми в каникулы», рядом с лагерями.

## Открытый вопрос: ИИ-запреты в robots.txt — решить до этапа 8
У Cambridge News, Cambridge Independent, Peterborough Telegraph и газет Newsquest в robots.txt закрыт доступ ИИ-агентам (в т.ч. anthropic-ai, ClaudeBot, Claude-User); у Cambridge BID — тоже. Наш сборщик ходит под обычным User-Agent (правило соблюдено формально), но тексты статей газет передаются в Claude, а статьи Cambridge BID — нет. Это непоследовательно.
- **Уточнение после этапа 6 (таблица `source_ai_policy`):** запреты разного уровня. Newsquest (Hunts Post, Cambs Times, Wisbech Standard, Ely Standard) закрывает в том числе `Claude-User` — агента, который действует по запросу пользователя, это самый прямой сигнал «не передавать наш контент в Claude». Cambridge News, Cambridge Independent и Peterborough Telegraph закрывают `anthropic-ai`, `ClaudeBot`, `Claude-Web` (и Independent — `Claude-SearchBot`): это обучение и поиск, `Claude-User` не закрыт. Cambridge BID — запрета нет. Возможный промежуточный вариант решения: уважать запрет там, где закрыт `Claude-User`. В флаге предусмотреть режимы: `off` / `claude_user_only` / `any_ai_agent`.
- **До моего решения на этапе 8** (на время разработки, без публикации): флаг остаётся `off`, ничего не менять. Решение — на этапе 8, когда будет посчитано, сколько теряем в каждом режиме.
- **Замер для решения:** в каждом отчёте о сборке выпуска (начиная с v4) показывать, сколько пунктов выпуска пришло **только** из источников с запретом `Claude-User` (сейчас — Newsquest S116–S119) и сколько — только из источников с запретом ботов обучения/поиска (S003, S004, S010, S092, S093). То есть что исчезло бы из выпуска в режимах `claude_user_only` и `any_ai_agent`.
- **Варианты решения:** (1) уважать ИИ-запрет везде — тексты таких источников в модель не передавать, только заголовки/ссылки и правила без модели + компенсация первоисточниками; (2) оставить как есть; (3) договориться с отдельными изданиями о разрешении.
- **Данные для решения** — пункт 5 этапа 6b (какая доля «газетных» пунктов находится через первоисточники).
- **Технически подготовить оба режима:** флаг в конфиге `respect_ai_disallow` (по умолчанию `false` до решения), который для источников с ИИ-запретом в robots.txt переключает извлечение на режим «только заголовок + ссылка, без модели». Список таких источников определять автоматически по robots.txt при каждой проверке источника.

## Правила
- Ключ Anthropic API — в переменной окружения `EVENTS_ANTHROPIC_KEY` (имя `ANTHROPIC_API_KEY` в облачных средах зарезервировано и в сессию не передаётся). Клиент: `Anthropic(api_key=os.environ["EVENTS_ANTHROPIC_KEY"])`.
- Уважать robots.txt, делать паузы между запросами, честный User-Agent.
- Не обходить Cloudflare и другую защиту от ботов.
- Не парсить Facebook, Instagram, Nextdoor.
- Не копировать описания дословно: ссылка на первоисточник и короткий пересказ.
- Ключи (Anthropic API и другие) — только в переменных окружения / `.env`, не в коде и не в git.
- Перед подключением платных сервисов или любыми тратами — спросить меня. Расход Claude API на извлечение из статей и черновик — показывать в отчёте.
- Python, простые зависимости: httpx, selectolax или BeautifulSoup, feedparser, icalendar. Playwright — только если без него никак.

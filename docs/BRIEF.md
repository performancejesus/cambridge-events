# Cambridge Events — бриф для Claude Code (v3, 27.09.2026)

## Что строим
Сборщик событий Кембриджа и окрестностей, который раз в неделю готовит черновик рассылки «что происходит на этой неделе и в выходные». Помимо афиши сборщик отслеживает жизненный цикл событий (анонсы, старт продаж, отмены) и открытия новых заведений и магазинов. Это MVP: всё работает в облачной среде cambridge-events, без платных сервисов, пока я не скажу иначе.

## География
Зона покрытия = **всё, что в пределах часа езды от Кембриджа** + **весь Кембриджшир целиком**, включая Питерборо и Fenland, даже если туда дольше часа.
- Внутри зоны: Ньюмаркет, Saffron Walden, Royston, Haverhill, Бери-Сент-Эдмундс (соседние графства, но до часа) — да; Wisbech, March, Питерборо (Кембриджшир, но около часа и дальше) — да.
- Вне зоны: всё, что дальше часа И не в Кембриджшире (например, Бишопс-Стортфорд, если дальше часа, Лондон).
- Проверка принадлежности графству — по postcodes.io: `admin_county == "Cambridgeshire"` или `admin_district == "Peterborough"`.
- Метка зоны у события: `центр` / `до 30 мин` / `до часа` / `Кембриджшир, дальше часа`. Последняя метка нужна, чтобы в выпуске такие события шли отдельной рубрикой «По графству» и не вытесняли городские.

## Входные данные
`data/cambridge_event_sources_v0.4.xlsx` — реестр источников (листы «Источники», «Проверка P1», «Схема события», «Категории и теги»).

## Этапы
Идём по одному. После каждого этапа — короткий отчёт и пауза до моего «дальше».

**Этап 1. Проверка источников с приоритетом 1.** ✅ Готово (`docs/stage1_report.md`).

**Этап 2. Коллекторы.** ✅ Готово (`docs/stage2_report.md`): 19 коллекторов, 0 падений, 674 события + 125 статей из RSS.

**Этап 3. Нормализация, хранилище и извлечение из статей.** ✅ Готово, кроме извлечения из статей — ждёт ключа API (`docs/stage3_report.md`). Доработки из раздела «Решения после этапа 3» выполнить до этапа 4.
1. **База** `events.db` (SQLite) с жизненным циклом событий и таблицей `venue_news` (см. разделы ниже). Сырые данные каждого прогона складываются в базу, прошлые события не удаляются — хранится история.
2. **Дедупликация.** Одно событие из нескольких источников — одна запись со списком источников. Особое внимание: Corn Exchange (S011) и Cambridge Live Tickets (S091) — один оператор; концерты дублируются на Ents24 (S006) и Skiddle (S007). Ключ сравнения: нормализованное название + дата + площадка, с нечётким сравнением названий.
3. **Справочник площадок** `venues`: название и синонимы → адрес, postcode, координаты, зона. Заполнить из событий, где адрес есть; колледжи, музеи и аудитории университета (talks.cam даёт postcode только у 6% событий) — добавить вручную или через postcodes.io. Событие без postcode получает адрес из справочника по названию площадки.
4. **Геокодирование** по postcode через postcodes.io, зона — по правилам раздела «География». События вне зоны не удалять, а помечать `out_of_zone` и не показывать в выпуске.
5. **Извлечение из статей через Claude API.** RSS-источники (Cambridge Independent, Cambridge News, What's On In Cambridge, Cambridge Foodies, Fitzwilliam, новостные фиды Cambridge 105) дают статьи, а не события. Для каждой новой статьи модель определяет, есть ли в ней: (а) событие с датой и местом, (б) открытие или закрытие заведения/магазина, (в) отмена или перенос известного события, (г) старт продажи билетов. Результат пишется в соответствующие таблицы с пометкой `source_type = article` и ссылкой на статью. Статьи без полезного содержания помечаются и больше не обрабатываются. Использовать дешёвую модель (Haiku), промпт и JSON-схему хранить в репозитории.
6. **Цены.** Где цена не пришла структурно, попытаться извлечь её со страницы события или из текста; «Free»/«free entry» → 0. Нужно для рубрики «бесплатно».
7. **Инкрементальный сбор.** Для источников, где открываются страницы событий (S011, S072, S091 и подобные), запрашивать страницы только для новых ссылок; уже известные — не чаще раза в неделю или при проверке статуса.
8. **Разовая выгрузка архива Cambridge Foodies** через `/feed/?paged=N` (редкие запросы, паузы, стоп после 429) → через извлечение из статей в `venue_news` за последние 12 месяцев.

**Этап 4. Черновик выпуска.**
События на ближайшие 7–10 дней + изменения за неделю. Через Claude API — отбор и короткие описания своими словами. Рубрики:
- главное на выходные;
- бесплатно; с детьми; спорт; за городом (до часа);
- по графству (Кембриджшир дальше часа: Питерборо, Fenland — только заметные события);
- новые анонсы (впервые появились за неделю, в т.ч. даты ежегодных событий);
- успейте купить билеты (продажа открылась или скоро откроется, мало билетов);
- отменено и перенесено;
- новое в городе (открытия ресторанов, кафе, баров, магазинов).
На выходе Markdown-файл.

**Этап 5. Контур отмен и изменений.**
Скрипт перепроверяет страницы отобранных событий на cancelled / postponed / sold out / on sale и пишет изменения в историю статусов.

**Этап 6 — только после моего подтверждения.** Запуск по расписанию: сбор **ежедневно** (иначе теряются короткоживущие события — Oktoberfest пропущен именно так), черновик выпуска — раз в неделю.

## Жизненный цикл событий
Статусы: `announced` (анонсировано, билетов нет) → `on_sale` (продажа открыта) → `sold_out` / `postponed` / `cancelled` → `past`.
Хранить: `first_seen_at`, `last_seen_at`, `on_sale_date` (если известна) и таблицу `status_history` (статус, дата изменения, источник). Каждый прогон сравнивает новые данные с базой и записывает изменения. Событие, пропавшее из источника до своей даты, не удалять, а помечать `disappeared` для ручной проверки (может означать отмену).

## Ежегодные события
Таблица `recurring_events` для крупных ежегодных событий, которые в начале цикла ещё не видны в афишах: название, ожидаемый месяц, официальный URL, способ проверки, дата последней проверки, найденная дата текущего года. Сборщик раз в неделю проверяет официальную страницу (если robots.txt разрешает и нет защиты от ботов) и новости; когда появляется дата — создаёт событие со статусом `announced`. Где сайт закрыт — дату вношу я вручную.
Стартовый список: Whittlesea Straw Bear (январь), Thriplow Daffodil Weekend (март), Cambridge Half Marathon (март), Cambridge Festival (весна), Cambridge Beer Festival (май), May Bumps (июнь), Strawberry Fair (июнь), Midsummer Fair (июнь), Cambridge Folk Festival (июль–август), Dragon Boat Festival ACT (сентябрь), Chariots of Fire (сентябрь), Open Cambridge (сентябрь), Cambridge Oktoberfest (сентябрь), Town and Gown 10k (октябрь, вручную — сайт за Cloudflare), фейерверки на Midsummer Common (ноябрь), Mill Road Winter Fair (декабрь).

## Решения после этапа 3
- **Статусы.** `announced` — только для событий, у которых продажа билетов ещё не открылась, но ожидается. События без билетов (бесплатные лекции talks.cam, ярмарки, парады) получают статус `scheduled` и в рубрику «Новые анонсы» попадают, только если появились впервые за неделю и заметны. Пересчитать текущие 122 `announced`.
- **Зона.** Расстояние по прямой от Market Square (центр ≤ 3 км, «до 30 мин» ≤ 25 км, «до часа» ≤ 60 км) — приемлемая замена времени в пути. Добавить метку `Кембриджшир, дальше часа` по правилам раздела «География». Разобрать 33 события с неопределённой зоной: почему нет postcode и можно ли взять адрес из справочника площадок.
- **Инкрементальный сбор** не сработал для Eventbrite (S008) и Cambridge Live Tickets (S091): 99 и 92 страницы запрошены заново. Кэшировать как у S011.
- **Ежегодные события.** Хранить не только дату начала, но и дату окончания (Straw Bear — фестиваль на выходные). Cambridge Folk Festival: начало вношу вручную.
- **Cambridge BID.** robots.txt закрывает сайт для ИИ-краулеров — уважаем волю владельца: статьи в Claude не передаём. Оставить только заголовки RSS с фильтром по ключевым словам (opening, opens, new, closing) без LLM, найденное класть в `venue_news` с пометкой «требует проверки».
- **Архив Foodies** — догружать не больше одной страницы в день, пока не дойдём до 12 месяцев.
- **Uniqlo.** Логика верная: магазины, которые были в списке ТЦ при первом прогоне, — база, не новые. Открытие ловится через статьи.

## Правила
- Уважать robots.txt, делать паузы между запросами, честный User-Agent.
- Не обходить Cloudflare и другую защиту от ботов.
- Не парсить Facebook, Instagram, Nextdoor.
- Не копировать описания дословно: ссылка на первоисточник и короткий пересказ.
- Ключи (Anthropic API и другие) — только в переменных окружения / `.env`, не в коде и не в git.
- Ключ Anthropic API — в переменной окружения `EVENTS_ANTHROPIC_KEY` (имя `ANTHROPIC_API_KEY` в облачных средах зарезервировано и в сессию не передаётся). Клиент создаётся явно: `Anthropic(api_key=os.environ["EVENTS_ANTHROPIC_KEY"])`.
- Перед подключением платных сервисов или любыми тратами — спросить меня. Расход Claude API на извлечение из статей и черновик — показывать в отчёте.
- Python, простые зависимости: httpx, selectolax или BeautifulSoup, feedparser, icalendar. Playwright — только если без него никак.
